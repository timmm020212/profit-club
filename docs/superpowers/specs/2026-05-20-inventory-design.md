# Спецификация: Складской учёт материалов

> Дата: 2026-05-20
> Статус: одобрено пользователем, готово к плану реализации
> Скоуп: v1 (MVP). Раздел «Материалы / Склад» в кабинете партнёра.

---

## 1. Цель и пользовательский сценарий

Партнёр (владелец салона) ведёт **полный учёт расходных материалов** так, чтобы:

- К каждому **варианту услуги** был привязан стандартный рецепт (например, «Окрашивание · длинные волосы»: 60 г краски + 90 мл оксида).
- При завершении записи система **автоматически предлагает** списать рецепт, мастер/партнёр может его поправить (фактический расход).
- Каждое **поступление материалов** (приход от поставщика) фиксируется как отдельная партия с ценой.
- Списание идёт **по FIFO** — старая партия расходуется первой, что даёт корректную себестоимость услуги.
- Текущий остаток виден всегда; ничего не «теряется» — каждое движение зафиксировано.

**Целевой пользователь:** партнёр в `/partner/inventory`. Мастер в мини-приложении — в v2.

**Не входит в v1:** см. раздел 7.

## 2. Модель данных

Все таблицы добавляются в `db/schema-postgres.ts`. Все — multi-tenant через `salonId integer not null`.

### 2.1 `materials` — каталог

```ts
export const materials = pgTable("materials", {
  id: serial("id").primaryKey(),
  salonId: integer("salon_id").notNull(),
  name: varchar("name", { length: 200 }).notNull(),
  unit: varchar("unit", { length: 16 }).notNull(),          // "g" | "ml" | "pcs" | "m"
  category: varchar("category", { length: 100 }),           // строка для v1; позже — отдельная таблица
  lowStockThreshold: numeric("low_stock_threshold"),        // опц.; для бейджа «низкий остаток»
  isActive: boolean("is_active").notNull().default(true),
  archivedAt: timestamp("archived_at"),
  createdAt: timestamp("created_at").defaultNow(),
});
```

### 2.2 `material_lots` — партии (каждое поступление)

```ts
export const materialLots = pgTable("material_lots", {
  id: serial("id").primaryKey(),
  salonId: integer("salon_id").notNull(),
  materialId: integer("material_id").notNull(),
  qtyInitial: numeric("qty_initial").notNull(),             // сколько пришло
  qtyRemaining: numeric("qty_remaining").notNull(),         // сколько ещё осталось (FIFO ↓)
  pricePerUnit: integer("price_per_unit").notNull(),        // копейки за единицу
  supplier: varchar("supplier", { length: 200 }),
  arrivedAt: varchar("arrived_at", { length: 10 }).notNull(), // YYYY-MM-DD
  note: text("note"),
  createdAt: timestamp("created_at").defaultNow(),
});
```

`pricePerUnit` хранится в **копейках за единицу** (целое число) — никаких float-ошибок при сложении.

### 2.3 `service_variant_materials` — рецепт варианта

```ts
export const serviceVariantMaterials = pgTable("service_variant_materials", {
  id: serial("id").primaryKey(),
  salonId: integer("salon_id").notNull(),
  variantId: integer("variant_id").notNull(),
  materialId: integer("material_id").notNull(),
  quantity: numeric("quantity").notNull(),
});
```

**Уникальность:** `(variantId, materialId)` — один материал в рецепте варианта не повторяется. Добавить unique index в миграции.

### 2.4 `appointment_material_usage` — фактическое списание

```ts
export const appointmentMaterialUsage = pgTable("appointment_material_usage", {
  id: serial("id").primaryKey(),
  salonId: integer("salon_id").notNull(),
  appointmentId: integer("appointment_id").notNull(),
  materialId: integer("material_id").notNull(),
  quantity: numeric("quantity").notNull(),                  // фактически списано
  totalCost: integer("total_cost").notNull(),               // копейки, агрегат
  lotsConsumed: jsonb("lots_consumed").notNull(),           // [{lotId, qty, price}]
  shortfall: numeric("shortfall").default("0"),             // если на складе не хватило
  createdAt: timestamp("created_at").defaultNow(),
});
```

`lotsConsumed` — массив JSON `{lotId: number, qty: number, price: number}` — audit trail. По нему можно полностью восстановить «откуда взяли и почём».

### 2.5 Расчётные величины (НЕ хранятся)

- **Текущий остаток материала** = `SUM(qtyRemaining)` по всем lots материала.
- **Средняя цена остатка** = `SUM(qtyRemaining * pricePerUnit) / SUM(qtyRemaining)`.
- **Себестоимость по рецепту варианта** (для подсветки в редакторе) = `SUM(recipe.quantity * среднюю цену материала)`.

Считаются на лету в API. Никакой кеш-таблицы — исключает рассинхронизацию.

## 3. Workflow списания

### 3.1 Триггер

Запись (`appointments`) переходит в статус `completed`. Это может произойти:
- из `AppointmentDetailModal` (новой кнопкой «Завершить» — нужно добавить);
- из мини-приложения мастера (в v2).

### 3.2 Pre-fill из рецепта

При срабатывании триггера UI открывает шаг **«Списать материалы»**:

1. Берёт `appointment.variantId`.
2. Загружает `service_variant_materials` WHERE `variantId = X`.
3. Для каждой строки делает строку списания: `{materialId, quantity: recipe.quantity}`.
4. Если у варианта нет рецепта (или у записи нет `variantId`) — список пуст, пользователь добавляет материалы вручную через `+ Добавить`.

### 3.3 Редактирование

Пользователь может:
- Изменить количество в строке.
- Удалить строку (если материал не использовался).
- Добавить материал вне рецепта через автокомплит из `materials` (например, ушёл дополнительный уход).

### 3.4 Подтверждение списания (бэк)

POST `/api/partner/appointments/[id]/usage` с массивом `{materialId, quantity}`.

Серверная транзакция:
```
для каждой строки списания:
  взять lots WHERE materialId=X AND qtyRemaining > 0 ORDER BY arrivedAt ASC, id ASC
  qtyLeftToAllocate = quantity
  consumed = []
  totalCost = 0
  для каждого lot:
    take = min(qtyLeftToAllocate, lot.qtyRemaining)
    lot.qtyRemaining -= take            (UPDATE)
    consumed.push({lotId: lot.id, qty: take, price: lot.pricePerUnit})
    totalCost += take * lot.pricePerUnit
    qtyLeftToAllocate -= take
    если qtyLeftToAllocate == 0: break
  shortfall = qtyLeftToAllocate         // если > 0 — на складе не хватило
  INSERT appointment_material_usage {appointmentId, materialId, quantity, totalCost, lotsConsumed: consumed, shortfall}
```

Транзакция оборачивается в `db.transaction()` — либо вся серия списаний проходит, либо ни одна.

### 3.5 Shortfall

Если на складе остаток меньше списываемого:
- Lot уходит в `qtyRemaining = 0`, **не в минус**.
- В `appointment_material_usage.shortfall` пишется недостающее количество.
- В UI после подтверждения показывается жёлтый баннер: «N материалов списано частично — внесите фактический приход».
- В разделе «Списания» такие записи помечаются значком ⚠.

Это сознательный выбор: салоны часто заводят склад постфактум, и блокирующая валидация будет мешать.

### 3.6 Отмена списания

В v1 — только soft-cancel: пользователь может удалить строку из `appointment_material_usage`, и серверная транзакция вернёт количество в самый старший списанный lot (восстановит `qtyRemaining`). Если lot уже исчерпан другими списаниями — возврат идёт в lot, который существует.

## 4. UI

### 4.1 Новая вкладка в сайдбаре

`PartnerShell.tsx` — добавить пункт `«Склад»` с иконкой коробки между `«Услуги»` и `«Отзывы»`. Путь: `/partner/inventory`.

### 4.2 Главная вкладки — три экрана через сегмент-таб сверху

```
[ Каталог ] [ Поступления ] [ Списания ]
```

#### 4.2.1 Каталог

Карточки материалов в стиле list-row (как `/partner/masters` / `/partner/clients`):

```
┌──────────────────────────────────────────────────┐
│ ◯  Краска L'Oréal Majirel 7.0   [Краски]  →    │
│ К   осталось 380 g · средняя 8.5 ₽/g · ⚠ низкий │
└──────────────────────────────────────────────────┘
```

Сверху:
- Кнопка `+ Новый материал` (primary)
- Поиск по названию
- Фильтр по категории (пилюли)

Бейдж «⚠ низкий» — если `currentStock < lowStockThreshold`.

Карточка клик → модалка деталей материала: история партий, история списаний, кнопка `+ Поступление`, кнопка «Архивировать».

#### 4.2.2 Поступления

Журнал партий. Сверху — `+ Поступление`, поиск, фильтр по дате/материалу/поставщику.

Карточка:
```
↑ Краска L'Oréal Majirel 7.0   +250 g   12 апр   1 980 ₽   →
                                                 Поставщик: КраскаОпт
```

Клик → модалка деталей партии (qtyInitial / qtyRemaining / список списаний из этой партии).

#### 4.2.3 Списания

Журнал по записям, сгруппирован по дням.

Карточка:
```
14:00 · Окрашивание · Анна П. / мастер Лена
       ↓ 45 g Краска L'Oréal · ↓ 100 ml Оксид 6%
       –780 ₽
```

Клик → деталь записи + список списанных материалов с разбивкой по партиям.

### 4.3 Модалки

#### Новый/редактирование материала (`MaterialEditor`)

Поля: имя, единица (radio: g / ml / pcs / m), категория (свободный input + автокомплит из существующих), низкий остаток (опц.), активность.

#### Поступление (`ArrivalEditor`)

Поля: материал (select из каталога, поиск), количество, цена за единицу ИЛИ общая сумма (взаимная конвертация), поставщик (строка), дата (по умолчанию сегодня), заметка.

#### Списание (`UsageEditor`) — встроено в `AppointmentDetailModal`

Сетка строк `{materialId, quantity}`:
- В каждой строке — select материала (с поиском), input количества с единицей, кнопка удалить.
- Внизу — `+ Добавить материал`.
- Кнопка `Подтвердить списание` — primary.
- Если есть рецепт — строки предзаполнены, в правом верхнем углу маленькая надпись «из рецепта · можно править».
- Если рецепта нет — пустой список + большая кнопка `+ Добавить материал` по центру с подсказкой «Привяжите расход к варианту услуги, чтобы в следующий раз заполнилось автоматически».

### 4.4 Интеграция в редактор варианта услуги (`ServiceEditor`)

Под существующими полями варианта (цена / длительность / название) — новый блок **«Расход материалов»**:

```
Расход материалов                           Себест-ть по средней: ≈ 510 ₽
┌─────────────────────────────────────┐
│ Краска L'Oréal Majirel 7.0   60 g  ✕│
│ Оксид 6%                     90 ml ✕│
└─────────────────────────────────────┘
        [+ Добавить материал]
```

API: `GET /api/partner/services/[id]/variants/[vid]/materials` / `PUT` (массивом).

### 4.5 Интеграция в `AppointmentDetailModal`

Текущая модалка имеет статусную полосу сверху. Добавляем:
- Кнопка **«Завершить»** в футере деталей (рядом с «Отменить» / «Перенести»), показывается когда статус `confirmed` или `pending` и запись прошла или сегодня.
- При клике — переключение в подмодалку `UsageView` (по аналогии с `RescheduleBody`): шапка «Завершение записи · списание материалов», тело — `UsageEditor`, футер — `Назад` / `Завершить и списать`.
- На «Завершить и списать» — два запроса транзакционно: `PATCH /api/appointments/[id]` со статусом `completed` + `POST /api/partner/appointments/[id]/usage`.
- Если в редакторе пуст список — основная кнопка автоматически переключается с «Завершить и списать» на «Завершить без списания» (вызывает только `PATCH /api/appointments/[id]` со статусом `completed`).

## 5. API

Все эндпоинты — под `requirePartnerSession`, фильтр по `session.salonId`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET`    | `/api/partner/materials` | Каталог + остатки (`currentStock`, `avgPrice`) |
| `POST`   | `/api/partner/materials` | Создать материал |
| `PATCH`  | `/api/partner/materials/[id]` | Изменить (имя/единица/категория/threshold/active) |
| `DELETE` | `/api/partner/materials/[id]` | Soft-delete (archived) |
| `GET`    | `/api/partner/material-lots` | Журнал поступлений (с фильтрами `?materialId&from&to&supplier`) |
| `POST`   | `/api/partner/material-lots` | Новое поступление |
| `GET`    | `/api/partner/services/[id]/variants/[vid]/materials` | Рецепт варианта |
| `PUT`    | `/api/partner/services/[id]/variants/[vid]/materials` | Перезаписать рецепт целиком |
| `GET`    | `/api/partner/usage` | Журнал списаний (с фильтрами `?appointmentId&from&to&materialId`) |
| `POST`   | `/api/partner/appointments/[id]/usage` | Подтвердить списание (транзакция FIFO) |
| `DELETE` | `/api/partner/usage/[id]` | Отменить одну строку списания (возврат в lots) |

Текущий остаток отдаётся в `GET /api/partner/materials` агрегатом — фронту не нужно делать N+1 запросов.

## 6. Edge cases

| Случай | Поведение |
|---|---|
| У услуги нет вариантов | Редактор материалов на странице услуги показывает плашку «Создайте вариант услуги, чтобы настроить расход». Никакого тихого фолбэка на услугу. |
| У записи нет `variantId` | Шаг списания открывается с пустым списком. Пользователь добавляет материалы вручную. |
| На складе остаток < списываемого | Lot обнуляется до 0, не в минус. `shortfall` пишется в usage. Жёлтый баннер в UI. |
| Удаление материала | Soft delete (`archivedAt`). Партии и история сохраняются. В выпадашках выбора материала архивные не показываются. В журналах — отображаются с пометкой «архив». |
| Изменение единицы существующего материала | Запрещено в UI (disabled + tooltip). Иначе прошлые количества теряют смысл. Если нужно — заводи новый материал. |
| Параллельное списание одного материала | Транзакция БД с `SELECT ... FOR UPDATE` на строки `material_lots` материала — избегает гонок. |
| Отрицательное списание (возврат, ошибка) | В v1 запрещено. Для отмены — DELETE на строку usage (возврат в lots). |

## 7. Сознательно не в v1

- Сроки годности (`expiresAt`) на партиях — поле зарезервируем, UI/алёрты позже.
- Категории через отдельную таблицу — пока строка.
- Поставщики через отдельную таблицу — пока строка.
- Списание из мини-приложения мастера — позже.
- Push-уведомления при низком остатке — позже (бейдж в UI уже есть).
- Импорт CSV / Excel.
- Инвентаризация (раз в месяц фиксируем «реально на полке = X», списываем разницу) — требует отдельной сущности `inventory_adjustments`.
- Перемещение между филиалами.
- Метод оценки кроме FIFO (LIFO, средняя).
- Закупки / заказы поставщикам (с подтверждением получения = создаст lot).
- Возврат поставщику.
- Аналитика себестоимости и маржи на отдельной странице — данные собираются, но визуализация позже.

## 8. Технические соглашения

- Все суммы денег — в **копейках** (`integer`). Конвертация в рубли только на UI.
- Все количества — `numeric` (decimal) с двумя знаками после запятой через тип `numeric(12, 2)` в миграции. Для краски/оксида двух знаков хватает.
- Единицы измерения — фиксированный enum в коде (`"g" | "ml" | "pcs" | "m"`), но хранятся как `varchar` чтобы можно было расширить без миграции.
- Все таблицы получают `salonId` index для скоростных выборок.
- Транзакции FIFO оборачивать в `db.transaction()` (Drizzle поддерживает).
- Миграция через `npm run db:push` (как и `reviews`). Скрипта переноса данных не нужно — таблицы пустые.
